Static Linking - Big in size, all is in the package (libs are packaged with the app itself)
Dynamic Linking - small in size, dependencies (the app needs to have dependencied installed additionally)

Packages solves this issue - tracks dependencies, easy installation and update of dependencies

Package contains:
System data
	- name
	- version
Actual content
	- binary files
	- config files
	- documentation files

Package formats:
.rpm - Red hat packages
.deb - Debian packages

Low level package management (They can only install, update, remove LOCAL PACKAGES):
- rpm (Red hat)
	- RPM Database - /var/lib/rpm
		- rpm --rebuilddb (can rebuild itself, in case the database is corrupted)
		- only one user can access the database at a time, which prevents problems (implemented by: /var/lib/rpm/.rpm.lock)
	- RPM Package files
		- source and binary
		- full, patch and delta (difference between two version is delta)
		- Contains - compressed binary files, name and version, build date and host, description, checksums and dependencies required
		- When asking for info about a package:
			- If it is already installed, the info comes from the rpm database
			- For not installed packages, it comes from the package itself, as it contains the meta data necessary for the info
	
- dpkg (Debian)
	- DEB Database - /var/lib/dpkg
		- again, only one user can work at a time (lock file: /var/lib/dpkg/lock
	- DEB Package files
		- source and binary
		- ar archive file
		- Three parts
			- Header - debian-binary
			- Control archive - control.tar.{gzip, xz}
			- Data Archive - data.tar.{gzip, xz, lzma}
		- When asking for info about a package:
			- If it is already installed, the info comes from the dpkg database
			- For not installed packages, it comes from the package itself, as it contains the meta data necessary for the info

High level package management (They can work with remote repositories, searching and downloading packages):
- yum and dnf (Fedora - Red hat)
- zypper (openSUSE)
- apt (Debian)

Storage types:
- Local
	(DAS - Direct-attached Storage - no network is needed, directly connected to the device)
	- Internal - SSD (solid-state), Hard drive (spindle) 
	- External - External Hard drive, USB
	
- Remote
	- File-based - Network-Attached Storage (NAS) - it is pretty much ready to use, once we connect to it
	- Block-based - Storage Area Network (SAN) - needs to be configured, someones gives us a block, which we put a file system on and configure it (it does not come ready to use out of the box).
	
Disk types:
- PATA (Parallel ATA) - /dev/hdX (128 - 1064 Mbps)
- SATA (Serial ATA) - /dev/sdX and /dev/srN (1.5 - 6.0 Gbps)
- SCSI (Small Computer System Interface) - /dev/sdX and /dev/srN
- NVMe (Non-Volatile Memory Express) - /dev/nvmeNnM (16 Gbps per lane, PCIe)

Measure Units:
- MB (megabyte) - 10^6 B = 1 MB (1 MB = 1000 KB = 1000 * 1000 B = 1000000 B)
- MiB (mebibyte) - 2^20 B = 1 MiB (1 MiB = 1024 KB = 1024 * 1024 B = 1048576 B)

Filesystem - the way the storage of data is organized on a disk or partition of a disk

Filesystem components
	- Superblock - contains the characteristics of the filesystem (size, block size, empty and filled blocks, size and location of the indoe t able). One main and multiple copies
	- Inode - data structure that stores all the information (metadata - file type, size, creation date, modification date, last opened date) about a file, except its name and data
	- Data block - contains the information stored in the individual files
	
Filesystem structure:
Super block (1 block) -> Group Descriptors (N blocks) -> Data Block Bitmap (1 block) -> Inode Bitmap (1 block) -> Indoe Table (N blocks) -> Data blocks (N blocks)

Filesystem types:
	- Extended filesystem - Ext(2,3,4)
	- Extents Filesytem - xfs
	- btrfs (copy-on-write filesystem)

Journaling - keeps track of filesystem changes
